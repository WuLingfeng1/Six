# 自动迭代运行手册

六子棋独立版（`程序原版压缩包/six`）的自对弈 / 参数迭代工具 `self_iteration` 的终端手动运行步骤。

下文命令用 **fish** 语法（用户实际 shell）；若用 bash，把 `env VAR=x cmd` 换成 `VAR=x cmd`、`; and` 换成 `&&` 即可。`candidate_runner.sh` 本身是 bash 脚本，fish 里也能直接执行。

## 0. 环境

- Qt 工具链：`/opt/Qt/6.11.1/gcc_64/bin/qmake`，`-spec linux-clang`，Release（`-O2`）。
- 构建和运行都要设 `QT_QPA_PLATFORM=offscreen`（无界面环境）。
- 源码根目录（下面记作 `$ROOT`）：`/wlf/Six/程序原版压缩包/six`。
- 工具目录（下面记作 `$SELF`）：`$ROOT/self_iteration`。

## 1. 构建 self_iteration（一次性）

```fish
mkdir -p $ROOT/self_iteration/reports/build
cd $ROOT/self_iteration/reports/build
/opt/Qt/6.11.1/gcc_64/bin/qmake -spec linux-clang $ROOT/self_iteration/self_iteration.pro -o Makefile CONFIG+=release CONFIG-=debug
make -j4
```

产物：`$ROOT/self_iteration/reports/build/self_iteration`（下面记作 `$BIN`）。

## 2. Smoke 验证（1 局、3 回合，跑通即可）

```fish
mkdir -p $ROOT/self_iteration/reports/smoke
env QT_QPA_PLATFORM=offscreen $BIN --mode baseline --games 1 --plies 3 --opening-set 0 --no-critical-regression --out $ROOT/self_iteration/reports/smoke
```

成功标志：输出 `illegal_count: 0`；目录里生成 `baseline.json` / `baseline.csv` / `baseline.md`。

## 3. 正式基线（带调参）

```fish
mkdir -p $ROOT/self_iteration/reports/baseline-run
env QT_QPA_PLATFORM=offscreen $BIN --mode baseline \
  --games 4 --plies 30 --opening-set 4 \
  --no-critical-regression \
  --max-depth 8 --q-max-nodes 2048 \
  --out $ROOT/self_iteration/reports/baseline-run
```

要点：

- `--out` 目录**必须先 `mkdir`**，程序不会自动建，否则报 `unsupported parameters or output directory`。
- `--plies 30` 才会下到分胜负；`--plies 10` 大概率全 `unfinished`。
- 看摘要：打开 `baseline-run/baseline.md`；看逐回合明细：`baseline.json`。

## 4. 自动迭代（一次扫多组参数）

编辑 `$SELF/candidate_runner.sh` 里的候选数组，然后运行：

```fish
cd $ROOT/self_iteration
./candidate_runner.sh --games 4 --plies 10 --opening-set 4
```

它会对每组合适的「评分权重 + 搜索参数」分别：复制源码 → 改参数 → Release 编译 → 跑基线 → 写报告到 `$SELF/reports/`。

### 候选 vs baseline 对打（真正测棋力）

加 `--match-games N` 就会让每个候选（attack/defense）跟 baseline 对打，由独立裁判 `match_runner` 判胜负。**这是唯一能测「候选棋力」的方式**（自对弈只能测开局平衡）：

```fish
cd $ROOT/self_iteration
./candidate_runner.sh --games 1 --plies 5 --opening-set 4 --match-games 4 --match-plies 30 --match-randomize
```

- `--match-games 4`：每个候选跑 3 场景（control / candidate-black / candidate-white）× 4 局。
- `--match-plies 30`：每局最多 30 回合（要下到分胜负）。
- `--match-randomize`：开启走法随机化（否则同开局两局一模一样，样本无效）。
- `--match-seed-base N`：对打随机种子基准（默认 1），第 i 局用 seed = N + i。
- 结果在 `reports/<候选>/match/match.json`：`scenarios`（三场景逐回合）、`comparisons`（候选相对 control 的首个分叉点）、`match.csv`（胜负汇总）。

读法：候选做黑比 `control` 的黑多赢 → 黑方更强；做白比 `control` 的白多赢 → 白方更强；两色都强 → 整体更强。

### 参数扫描（自动生成候选 + 排名）

`--scan N` 会自动随机生成 N 个候选（扰动 7 个评分权重 + 随机选 maxDepth/qMaxNodes/qMaxPly），逐个 build + match，最后按「相对 baseline 的净胜局」排名：

```fish
cd $ROOT/self_iteration
./candidate_runner.sh --games 1 --plies 5 --opening-set 0 \
  --scan 10 --scan-seed 42 \
  --match-games 20 --match-plies 30 --match-randomize
```

- `--scan N`：随机候选数量（1..40），替代手写的 attack/defense 三组。
- `--scan-seed S`：候选生成种子（默认 1），同 seed 生成的候选集一样。
- 生成结果存 `reports/scan-specs.json`（每候选的权重+参数）。
- 排名存 `reports/scan-ranking.md` / `.csv`：`net = (做黑多赢的局) + (做白多赢的局)`，正数 = 强于 baseline。

这是「自动迭代」的雏形：跑一轮 scan → 看 `scan-ranking.md` 里 net 最高的候选 → 把它的权重/参数抄进 `WEIGHTS`/`SEARCH_PARAMS` 作为新 baseline，再 scan，往复。真正的闭环（自动把胜者设为下一轮 baseline）尚未实现，目前需要手动抄。

### 全自动闭环迭代（`iterate_runner.py`）

`iterate_runner.py` 把「生成候选 → 对打 → 把胜者设为下一轮 baseline」全自动连起来：

```fish
cd $ROOT/self_iteration
python3 iterate_runner.py --iterate 3 --scan 5 --scan-seed 42 \
  --match-games 4 --match-plies 30 --match-seed-base 1
```

- `--iterate K`：迭代轮数（1..20）。每轮：
  1. 随机生成 `--scan` 个候选（每轮用 `scan-seed + 轮次` 做种子，候选集不同）；
  2. 逐个 build + 与**当前 baseline** 对打；
  3. net 最高且 > 0 的候选成为下一轮 baseline（直接复用它的二进制，无需重编）。
- `--baseline-weights` / `--baseline-params`：可指定起始 baseline（默认生产权重）。
- 报告在 `reports/iterate/iterate-history.{json,md,csv}`：每轮的 baseline、是否提升、胜者、net、胜者权重/参数。

这是真正的「自动迭代闭环」：跑 K 轮，胜者自动继承，收敛轨迹全记录。注意每轮都要跑 `scan × 3 场景 × match-games` 场对打，`--iterate 3 --scan 5 --match-games 4` 约需 1 小时量级，先用小参数试通。

候选定义在脚本顶部：

```bash
declare -a IDS=(baseline attack defense)
declare -a WEIGHTS=(          # 7 个评分权重
    '0,1,20,300,2000,6000,100000'
    '0,1,25,350,2300,6500,100000'
    '0,1,18,280,2200,6500,100000'
)
declare -a SEARCH_PARAMS=(    # 搜索参数，key=value 空格分隔，空串=默认
    ''
    'maxDepth=8 timeLimitMs=3000'
    'qMaxNodes=2048 qMaxPly=3'
)
```

## 5. 命令行参数

### 模式与对局

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `--mode` | `baseline` / `worker` | 自对弈基线 / 对打 worker（stdin 协议） |
| `--games` | 1..40 | 局数，按 `game % opening_set` 轮流分配开局 |
| `--plies` | 1..30 | 每局最多双子回合数 |
| `--opening-set` | 0/1/2/4 | 固定开局数量（0=不强制开局） |
| `--out` | 已存在目录 | 输出目录，必须先 mkdir |
| `--no-critical-regression` | — | 跳过关键局面 oracle（smoke 用） |

### 搜索参数（可选，缺省用默认值）

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| `--time-limit` | 2000 | 单步搜索预算（ms） |
| `--probe-budget` | 1100 | 已知反例传播预算（ms） |
| `--probe-discovery` | 200 | 反击发现预算（ms） |
| `--probe-points` | 28 | 反击候选点数 |
| `--probe-replies` | 32 | 反击回复对数 |
| `--q-max-ply` | 2 | 防守延伸层数 |
| `--q-max-nodes` | 1024 | 防守延伸节点预算 |
| `--q-max-defenses` | 16 | 防守分支上限 |
| `--max-depth` | 6 | 迭代加深最大深度 |
| `--root-max-points` | 40 | 根层候选点数 |
| `--root-max-pairs` | 25 | 根层候选对子数 |
| `--inner-points` | 18 | 内部候选点数 |
| `--inner-pairs-deep` | 35 | 深度 ≥2 的候选对子数 |
| `--inner-pairs-shallow` | 20 | 浅层候选对子数 |
| `--randomize` | 关（flag） | 开启走法随机化（打破确定性） |
| `--random-top-n` | 5 | 随机时只考虑得分前 N 的走法 |
| `--random-temp` | 2000.0 | 软最大化温度，越大越均匀（越小越倾向最优） |
| `--seed` | 0 | 随机种子；0=每次不同，非 0=固定种子 |

## 6. 固定开局表

| id | 棋谱坐标 |
| --- | --- |
| 0 | I10, K12 |
| 1 | L7, H14 |
| 2 | H11, L9 |
| 3 | G8, M12 |

`--opening-set 4 --games 4` = 4 个开局各 1 局；`--games 8` = 各 2 局，依此类推。

## 7. 已知限制

- **确定性自对弈**：同开局 + 同引擎 + 同参数，每一步 `bestPlay()` 结果完全相同，所以同开局的「多局」只是重复同一局。加 `--randomize` 可打破（在得分前 N 的走法里按分数加权随机选），配合 `--games 8 --opening-set 4` 让同开局的局也能下出不同对局。
- **随机化的两个注意点**：
  - 加权随机「倾向最优」：若某步存在明显占优的唯一解，`--randomize` 也可能每次都选它（同开局仍可能重复）。要更多变化可调大 `--random-temp`（如 5000）。
  - `--seed` 只能保证「大致可复现」：搜索本身是限时（2000ms）的，跨进程跑两次即使同 seed，墙钟时间细微差异也可能让搜索完成深度不同，导致结果略有出入。这是限时搜索的固有特性，与随机化无关。
- `--plies 10` 通常不足以分胜负，正式对比用 `--plies 30`。
- 关键局面 oracle 只是一层安全判定（`safe_one_reply`），不是整局必胜证明；正式对比不要用 `--no-critical-regression` 关闭它。
- 报告会写 SHA256（`source_sha256_game` / `config_sha256`）便于追溯版本。
