# 自动迭代运行手册

适用独立版 `程序原版压缩包/six`。以下使用 bash；在该源码目录执行。棋力比较使用 Qt 6.11.1、linux-clang、Release/O2，搜索进程串行运行，避免相互争抢 2000ms 搜索预算。报告保存在 `self_iteration/reports/`，该目录被 Git 忽略，但保留在磁盘。

## 历史结果更正（2026-10-21）

旧 `self_iteration.pro` 无条件写入 `GAME_DIR = ..`，覆盖命令行候选目录。已核对旧 `threat-20` 两侧 Makefile，实际均编译生产 `Game.cpp`；这些历史 A/B 不再作为参数或算法收益的证据。之前仅比较候选副本的哈希不足以确认实际构建输入。

现在 qmake 保留传入的 `GAME_DIR`，优先使用候选头文件，并在编译时嵌入源码 SHA256。三个候选构建入口都调用 `verify_worker.py`，核对运行时默认参数与候选头文件、编译指纹与候选源文件；失败就停止该候选。修改源码后必须重新 make。

## 构建与验证

```bash
mkdir -p self_iteration/reports/build
/opt/Qt/6.11.1/gcc_64/bin/qmake -spec linux-clang self_iteration/self_iteration.pro -o self_iteration/reports/build/Makefile CONFIG+=release CONFIG-=debug
make -C self_iteration/reports/build -j4
python3 self_iteration/verify_worker.py "$PWD/self_iteration/reports/build/self_iteration" "$PWD"
```

默认参数检查：

```bash
QT_QPA_PLATFORM=offscreen self_iteration/reports/build/self_iteration --mode config
```

返回 `search_config`、`config_sha256`、`compiled_sources`、`tt_effective` 和 Qt 版本。配置哈希来自完整运行时 SearchConfig；编译指纹包括 Game/Move 源码和头文件、runner、开局表。`--source-root` 不再决定编译指纹。

## 自对弈与战术回归

```bash
mkdir -p self_iteration/reports/baseline-run
QT_QPA_PLATFORM=offscreen self_iteration/reports/build/self_iteration --mode baseline --games 8 --plies 30 --opening-set 8 --randomize --seed 42 --out self_iteration/reports/baseline-run
QT_QPA_PLATFORM=offscreen self_iteration/reports/build/self_iteration --mode tactics --out self_iteration/reports/tactics/current
```

- baseline：最多 40 局、每局最多 30 个双子回合；`--out` 必须已存在。时间预算、完整参数和编译源码指纹写入 JSON，Markdown 使用实际预算。
- 默认执行关键局面回归。`--no-critical-regression` 只用于工具 smoke；正式实验保留回归门槛。
- white15、turn17 使用 `tests/fixtures/` 中的原谱副本，不依赖 `/tmp`。离线测试可用 `SIX_WHITE15_RECORD` / `SIX_TURN17_RECORD` 指定其他完整原谱。
- tactics 自动创建输出目录；45 题按 `pass/fail/unknown/lost/control/invalid` 分别计数。fail、unknown、invalid 会使命令非零退出；lost 仍单列，不表示通过。
- 一回复安全不是整局必胜。自对弈胜负比例主要描述该引擎和这些开局的行为，不能替代候选对旧版的比较。

## A/B 对打

```bash
bash self_iteration/ab_compare.sh --old-commit HEAD --games 8 --plies 30 --opening-set 8 --seed-base 201 --out-root "$PWD/self_iteration/reports/ab-current"
```

指定参数比较，例如威胁延伸：

```bash
bash self_iteration/ab_compare.sh --old-params 'threatExtension=false' --new-params 'threatExtension=true' --games 8 --plies 30 --opening-set 8 --seed-base 201 --out-root "$PWD/self_iteration/reports/threat-201"
bash self_iteration/ab_compare.sh --old-params 'threatExtension=false' --new-params 'threatExtension=true' --games 8 --plies 30 --opening-set 8 --seed-base 301 --out-root "$PWD/self_iteration/reports/threat-301"
```

`--old-params` 使用当前源码副本构建旧侧，此时 `--old-commit` 不参与取源码。`--build-only` 只构建和核验两侧。支持 bool、整数、浮点 SearchConfig 字段；未知字段、重复字段和非法值会拒绝。每次实验使用不同输出目录，避免覆盖旧报告。

每组运行 control（baseline 双方）、candidate-black、candidate-white 三场景；`--games 8` 是 24 盘。每盘记录 seed、opening_moves 和 transcript；顶层记录两侧实际配置及编译指纹。`progress.json` 和 `match/stderr` 可查看进度。超时、启动失败或非法着法会令 match 返回失败，未完成对局保留为 unfinished。

`net = (候选执黑胜局 - control 黑胜局) + (候选执白胜局 - control 白胜局)`。同时查看失败状态、未完成比例、着法分叉和不同开局表现；小样本 net 不是统计显著性结论。默认威胁延伸开启时 TT 不使用，所以开关实验包含这一默认联动；若只比较延伸本身，可在两侧同时设置 `ttEnabled=false`。

结束后，用独立 Python 裁判重放两组完整棋谱并汇总：

```bash
python3 self_iteration/summarize_match.py self_iteration/reports/threat-201/match/match.json self_iteration/reports/threat-301/match/match.json --out self_iteration/reports/threat-summary.json
```

它逐子核对坐标、黑白轮次、六连、终局后落子、半回合、最终落子数及报告胜负；任何不一致都会报错。

## 扩展开局与中盘验证

需要扩展到中盘真实续弈和新的独立种子时，使用 [中盘评测说明](midgames/README.md) 中的
`validation_runner.py`。它在开赛前冻结输入，默认运行两组开局与两组中盘，共 96 盘；
按两类局面分别统计，并支持验证后续跑。中盘模式下 `match_runner --position-suite ... --games N`
表示每个局面重复 N 次，完整前缀会随报告保存。

## 有效棋型权重与参数扫描

当前八项权重按以下顺序传入：

| SearchConfig 字段 | 默认值 | 含义 |
|---|---:|---|
| shapeSingle | 1 | 单子 |
| shapeOpenTwo | 20 | 活二 |
| shapeClosedThree | 100 | 冲三 |
| shapeOpenThree | 1000 | 活三 |
| shapeClosedFour | 3000 | 冲四 |
| shapeOpenFour | 20000 | 活四 |
| shapeFive | 60000 | 至少一端开放的五连 |
| shapeSix | 100000 | 六连静态评分；终局 WIN_SCORE 独立 |

默认串是 `1,20,100,1000,3000,20000,60000,100000`。旧七项 road 权重不影响当前搜索，工具现在明确拒绝旧格式。所有权重必须在创建/播种 Game 之前设置，避免使已有棋线缓存失效。

```bash
QT_QPA_PLATFORM=offscreen self_iteration/reports/build/self_iteration --mode config --shape-weights '1,25,120,1200,3300,23000,65000,100000'
bash self_iteration/candidate_runner.sh --scan 5 --scan-seed 42 --games 1 --plies 1 --opening-set 8 --match-games 8 --match-plies 30 --match-opening-set 8 --match-randomize --out-root "$PWD/self_iteration/reports/scan-new"
```

候选通过统一的 `config_tools.py` 修改源码副本并保留 CRLF；不会写回生产。参数扫描排名使用每个候选自己的 control，不共用其他候选的 control 结果。手写 attack/defense 候选保持同一 2000ms 默认时间预算。

## 闭环迭代

```bash
python3 self_iteration/iterate_runner.py --iterate 3 --scan 5 --scan-seed 42 --match-games 8 --match-plies 30 --match-opening-set 8 --match-seed-base 201 --confirm-seed-base 301 --out-root "$PWD/self_iteration/reports/iterate-new"
```

每轮围绕当前 baseline 的八项权重扰动，并继承其余搜索参数；搜索深度/q 参数从预设集合取值。基线和每个候选先做关键局面回归，候选必须在两组不同种子下 net 均 >0 才能继承为下一轮基线。此门槛只是筛选，仍需更多独立样本复核。胜者仅用于实验的下一轮，不自动修改生产源码。

JSON 保留每个候选两组 net、是否有资格继承、错误以及下一轮来源。大轮次开销很高，先用 `--iterate 1 --scan 1 --match-games 1 --match-plies 1` 检查流程。

## 常用搜索开关

| 开关 | 默认值 |
|---|---:|
| --time-limit / --max-depth | 2000 / 6 |
| --probe-discovery / --probe-budget | 200 / 1100 |
| --probe-points / --probe-replies | 28 / 32 |
| --root-max-points / --root-max-pairs | 40 / 25 |
| --inner-points / --inner-pairs-deep / --inner-pairs-shallow | 18 / 35 / 20 |
| --q-max-ply / --q-max-nodes / --q-max-defenses | 2 / 1024 / 16 |
| --random-top-n / --random-temp | 5 / 2000 |
| --threat-max / --threat-budget | 2 / 64 |

`--randomize` 开启随机选择，`--seed` 指定种子；限时搜索仍会受机器负载影响。`--tt-off` 关闭 TT，`--threat-extend` / `--no-threat-extend` 显式控制威胁延伸。固定深度比较可使用较大 `--time-limit`，并检查实际 completed_depth。

## 开局表

由 `openings.h` 统一供 worker 和裁判使用；黑首子均为 J10。前四个编号保持原定义，新增四个用于扩展验证。

| id | 白方首双子 |
|---|---|
| 0 | I10 K12 |
| 1 | L7 H14 |
| 2 | H11 L9 |
| 3 | G8 M12 |
| 4 | I11 K11 |
| 5 | J11 L10 |
| 6 | H10 K11 |
| 7 | I12 L9 |

`--opening-set N` 使用前 N 个开局（1..8），按 game_index % N 轮换；baseline 另支持 0，不强制白方开局。

离线 GUI/规则回归见 [tests/README.md](../tests/README.md)，历史局面分析与真实续弈的区别见 [README.md](README.md)。
